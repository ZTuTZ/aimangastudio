# AIMangaStudio v2 Phase 7.7 端到端验收清单

> 本清单由人工执行(涉及真实 AI 调用与宕机演练)。
> 自动化覆盖:41 个单元测试(任务可靠性/并发引擎/素材绑定/Importer/长文拆分等)已全部通过。
> 执行环境:本地后端(8090)+ 前端(5173)+ MySQL + Redis,配置好 image/text 通道密钥。

---

## 测试 A:短篇(2~3 话)

1. 上传 1~2 万字 TXT → 观察自动流水线 SPLIT → ASSET → SCRIPT 全绿,项目变「待出图」
2. 资产库:勾选 2~3 个主角 → 生成设定表(并发观察任务进度 3/3)
3. 生成成品 → 多话选择 → 全选 → 开始生成
4. **预期**:布局阶段 → 成品阶段自动连续完成;页画廊逐页出图;项目状态变「完成」;无封面时自动取第一张成品页

## 测试 B:中篇(20 话)

1. 上传 10 万字级原文,重复 A 流程
2. **预期**:SPLIT 滚动分包正确(话数与内容边界合理);SCRIPT 逐话并发(脚本池),不占用生图并发;BATCH 中途暂停:
   - 点「暂停」→ 在跑的请求完成后保存,不再领取新页;任务正常结束
   - 点「继续流水线」→ 从未完成页继续,已成功页(布局+成品)**零重复计费**(看生成记录/任务 success 计数)

## 测试 C:长篇(50 话+)

1. 上传 25 万字级原文
2. **预期**:全流程无卡死;页画廊按话折叠可浏览;`pipeline_stage` 的 total/success/failed 与实际一致

## 测试 D:3 部作品同时 BATCH

1. 三部已就绪作品同时点开始生成
2. **预期**:
   - 生图并发总数不超过 `image_generation_concurrency`(看日志 `[stage] ... 并发=N` 与 AI 通道占用 `used/total`)
   - SCRIPT 与生图互不挤占(脚本池独立)
   - 管理员「任务监控」能看到 3 个项目的阶段聚合进度;AI 通道占用实时变化
   - 暂停其中一部,另两部不受影响

## 异常与边界项

| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| E1 | 服务重启恢复 | BATCH 进行中 kill 进程 → 重启 | Recovery 重入队 BATCH;SUCCESS 页跳过,PENDING/RUNNING 页续跑,无重复计费 |
| E2 | Redis 临时不可用 | 重启 Redis 后立即发起任务 | 任务报错可重试,不产生孤儿数据;信号量在启动时重置 |
| E3 | 单页失败 | 临时改错 image api_key → 跑 BATCH | 该页重试 3 次后 FAILED,其他页成功;项目变「部分失败」;失败页画廊显示原因;修复后单页重生成成功 |
| E4 | 单素材失败 | 同上改 key 跑设定表 | 失败角色标 FAILED;重跑 SHEET 任务只补失败/缺失角色 |
| E5 | 连续快速点击 | 资产库同一批素材连点 2 次生成 | 只创建/复用一个任务(Item 不重复,Stage 互斥锁生效) |
| E6 | 成功素材重生成 | 对已有设定表的角色点「重生成」 | 真实发起新生图并替换 sheet_image_url |
| E7 | 素材 Gate | 关掉 Gate(0)跑缺角色作品 | 仅警告放行;开回(1)后同样请求被拒 |
| E8 | 直出开关 | 开启 page_direct_output 跑 BATCH | 无布局阶段,直接出成品;页详情布局栏显示"尚未生成布局图" |
| E9 | 发布校验/导出 | 完成作品:发布导出页校验+导出;未完成作品同样操作 | 完成的可下载 ZIP(manifest.json+图片);未完成的列出全部 ERROR 项 |
| E10 | 导入还原 | 将 E9 的 ZIP 解包,取 manifest.json 交给 Importer(或核对字段) | 还原 漫画→话→页,全程不含生产系统任何 ID |
| E11 | 脚本版本失效 | 成品生成后编辑页脚本并保存 | 详情页出现「成品已过期」;画廊卡片显示「脚本已改」;BATCH 重跑只重画该页 |
