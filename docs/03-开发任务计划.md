# v2 开发任务计划

> 执行方式：**逐任务开发，每个任务完成后提交用户审核，通过后才进入下一任务**。
> 每个任务包含：目标 / 产出 / 验收标准（可自测）/ 审核要点。
> 任务顺序即依赖顺序；Phase 内任务一般可独立验收。

## Phase 1 工程骨架（可运行的空壳）

### T1.1 后端骨架 + 数据库
- **目标**：v2/server Spring Boot 3 工程可启动；新库建表完成。
- **产出**：`v2/server/pom.xml`、`AimangaV2Application`、`application.yml`（DB_*/REDIS_*/JWT_SECRET 环境变量，无默认密钥）、统一响应体 `{code,message,data}` + 全局异常处理、MyBatis-Plus 配置、Redisson 配置；`v2/server/sql/schema.sql`（user/project/chapter/page/asset/task/system_config/style_preset 全表）+ `seed.sql`（系统配置项 + 默认提示词模板 + 3 个风格预设）。
- **验收**：`mvn compile` 通过；本地执行 SQL 后 `SHOW TABLES` 8 张表；应用启动无报错，能连上 MySQL 与 Redis（`/api/health` 探针返回 db/redis 均 UP）。
- **审核要点**：表结构是否符合 02 文档 §2；配置是否全部外置无硬编码密钥。

### T1.2 前端骨架 + 主题
- **目标**：v2/frontend Vite + React 18 + TS + AntD 5（zhCN + 定制主题）+ Tailwind + Router + TanStack Query + zustand 骨架可运行。
- **产出**：工程初始化、目录结构（02 §7）、BasicLayout（侧边导航 + 顶栏，导航项占位）、路由表与占位空页面、axios 实例（拦截器骨架）、dev 代理 `/api` → 8090（`vite.config.ts`，可用 `VITE_API_TARGET` 覆盖）、AntD 主题 token（品牌色/圆角/字体）。
- **验收**：`npm run dev` 打开后看到完整布局壳，导航可切换占位页；`tsc --noEmit` 与 `npm run build` 通过。
- **审核要点**：视觉基调（主题色、布局风格）是否满意——**此处定调，后续页面沿用**。

## Phase 2 认证与账号

### T2.1 登录 / JWT / 角色守卫
- **产出**：`POST /api/auth/login`、`/refresh`、`GET /api/auth/me`、`POST /api/auth/password`；Apache Shiro SecurityManager + 自定义 JWT Filter/Realm（无状态，禁用默认 Session/Cookie）、JWT 工具、BCrypt；前端 Login 页、authStore、路由守卫（未登录跳登录、USER 访问 /admin 403 页）、401 自动刷新。
- **验收**：用 seed 的初始管理员登录成功进入布局壳；改密后旧密码失效；token 过期自动续期；USER 账号访问 /admin/users 被拦截。
- **审核要点**：登录页视觉与交互。

### T2.2 管理员账号管理（后端 + 前端）
- **产出**：`GET/POST /api/admin/users`、`PUT /api/admin/users/{id}`（停用/启用/重置密码）、`DELETE`（高危：需请求体重复用户名确认）；前端 `/admin/users` 列表 + 新建/编辑弹窗。
- **验收**：管理员创建 USER 账号并用其登录；停用后该账号登录被拒；重置密码生效；删除需输入用户名确认。

## Phase 3 基础数据层 + AI/存储服务

### T3.1 作品/话/页/资产 CRUD 与导入
- **产出**：project/chapter/page/asset 四组 Service + Controller（含归属校验）、`POST /api/projects/import`（多文件 TXT/DOCX，POI 解析；标题默认文件名）、作品状态机字段维护；前端作品库页（卡片网格 + 批量上传弹窗 UploadStories）+ 作品详情骨架（Tabs）。
- **验收**：上传 2 个 TXT → 生成 2 部作品；详情页能看话/页/资产空列表；删除作品级联清理；USER 只能看到自己的作品。
- **审核要点**：作品库卡片视觉与上传交互。

### T3.2 OSS 存储服务
- **产出**：`OssStorageService`（byte[]/URL 下载两种上传、对象键 `{dir}/{userId}/{yyyyMMdd}/{ts}_{rand}.{ext}` ASCII 化、`oss_image_process` 缩略参数拼接）、`POST /api/files/upload`、未配置 OSS 时明确报错。
- **验收**：上传参考图返回可访问 OSS URL；oss_image_process 生效；未配置密钥时上传返回"请先在系统配置中填写 OSS 参数"。

### T3.3 AI 服务层 + 提示词配置
- **产出**：`AiClient`（双协议：Gemini generateContent / OpenAI images，超时重试日志）、`AiService`（chat/chatJson/generateImage，三种响应格式解析，base64→OSS）、`PromptService`（占位符渲染）、`/api/admin/configs`（脱敏读写 + verify 连通测试）与提示词编辑接口；MockWebServer 单测覆盖三种响应。
- **验收**：配置真实 GeekAI Key 后，管理端"测试连通"文本/生图各成功一次；`chatJson` 首次返回非法 JSON 第二次合法 → 成功；生图 URL 自动转存 OSS。
- **审核要点**：管理端配置页分组与脱敏展示。

## Phase 3.5 漫画内容兼容层

> 详见《AIManga_v2_Phase3.5_漫画内容兼容改造执行文档.md》与 `aimanga_v2_phase3_5_migration.sql`。

### T3.5.1 作品元数据字段 + content_uid
- **产出**：project 表新增 content_uid(UNIQUE)/description/cover_url/category/tags(JSON)/series_status；Entity/VO/Update DTO 同步；存量回填 UUID；新作品自动生成 UUID；作品详情支持维护短简介/正式简介/封面(OSS 上传)/主分类/标签/连载状态；content_uid 不可编辑；导出 DTO 契约 `dto/export/ComicManifest*`(comic-content-1.0)。
- **验收**：存量作品 content_uid 全且唯一；新建/批量导入互异；改标题/重拆话不影响 content_uid；元数据可读写；tags 非法 JSON 被 400 拦截。
- **审核要点**：详情页元数据编辑交互；content_uid 展示与复制。

## Phase 4 任务系统（重构核心）

### T4.1 任务状态机 + Redis 队列 + Worker
- **产出**：TaskService（create/list/get/stop/retry/delete）、TaskQueue（Redisson 队列）、TaskWorker 线程池（可配 worker 数）、TaskRunner 模板（状态流转/计数/终态）、`POST/GET /api/tasks` 系列 API；重启恢复器（ApplicationReadyEvent 扫描重入队）。
- **验收**：创建一个 mock 任务类型 → 状态 PENDING→RUNNING→SUCCESS；创建 5 个任务且 worker=2 → 始终只有 2 个 RUNNING；服务重启后未完成任务自动恢复执行；**任务创建/停止/重试/重启恢复全过程中 project.content_uid 始终不变化**。
- **审核要点**：状态机与 01 文档 §5 一致。

### T4.2 分层并发控制
- **产出**：每用户 Redisson 信号量、AI 通道（text/image/merge）Redisson 信号量接入 AiService、配置热更新（保存后 trySetPermits / 重建 worker 池）；并发单测。
- **验收**：user_concurrency=2 时同一用户第 3 个任务排队（状态保持 PENDING）；image 通道 concurrency=2 时 5 个并发生图请求实际同时最多 2 个在途（日志验证）；修改配置即时生效。

### T4.3 SSE 进度推送
- **产出**：`GET /api/tasks/events`（SseEmitter + Redis Pub/Sub 订阅、按用户过滤）、事件类型 task.created/progress/status/page.generated；前端 useSseTasks hook + 任务中心页（列表/筛选/进度条/停止/重试/删除，实时更新 + 断线降级轮询）+ 顶栏任务活动角标。
- **验收**：两个浏览器会话分别登录不同用户，各只看到自己任务进度；任务进度变化 ≤2s 反映到界面；断开网络后恢复自动重连。

## Phase 5 第一步流水线（准备）

### T5.1 SPLIT 拆话 + SCRIPT 六段式脚本
- **产出**：SPLIT 任务（拆话校验/重建话/链式入队 SCRIPT，**首次处理时生成作品元数据 tagline/description/category/tags/series_status，字段已有人工值时默认不覆盖，payload.refreshMetadata=true 才强制覆盖**）、SCRIPT 任务（StoryScript 契约 + 契约校验：空页拒绝、speaker 校验、无标点校验 + 重试；写 chapter/page；建资产素材）；导入作品自动入队 SPLIT 的编排；提示词默认模板迁移并强化（对白逐字保留原文、按原文顺序）。
- **验收**：上传一篇 3000 字小说 → 自动拆 2~8 话 → 每话脚本就绪（页数=storyboard_page_count 或 AI 返回值）→ 作品状态变"待出图"；脚本含旁白/对白/画面且无空页；对白 speaker 全部在资产列表中；**SPLIT 元数据已写入且 tags 为合法 JSON 数组、category 不在约定分类时归为"其他"；人工已填写的元数据不被覆盖**。
- **审核要点**：脚本质量（是否忠于原文、分镜描述是否专业）——**请用真实故事文本验收**。

### T5.2 ASSET 资产提取 + SHEET 角色设定表
- **产出**：ASSET 任务（四类资产结构化提取、同人合并 aliases）、SHEET 任务（角色六姿势设定表、单资产重生成接口）；作品详情"剧本与资产"Tab 前端：话列表（展开页脚本编辑、单话重跑脚本）、资产四类管理（结构化表单、参考图上传、生成设定表按钮）。
- **验收**：流水线结束后资产列表含角色（结构化字段完整）；手动编辑资产描述后重新生成设定表成功；页面脚本编辑保存后重新出图使用新脚本。
- **审核要点**：资产编辑交互与设定表质量。

## Phase 6 第二步流水线（出图）

### T6.1 BATCH 整部/按话一键生成
- **产出**：BATCH 任务（范围校验"脚本就绪"、收集页、空脚本页跳过、skipGenerated、页级并发 LAYOUT→PAGE、失败页 fail_reason、断点续跑 retry）、PAGE/LAYOUT 单页任务；前端"生成成品"Tab（范围/色彩模式/跳过已生成/一键提交 + 内嵌进度）。
- **验收**：选整部剧一键生成 → 全部页依次出图（页画廊实时填充）；中途停止 → retry 从失败页续跑且已成功页不重生成；3 部作品同时 BATCH 并行互不阻塞；**整部完成后若 cover_url 为空，按 chapter_no/page_no 顺序取第一张成功成品页写入默认封面（人工已设置则不覆盖）；只有 generate_status=2 且 generated_image_url 非空的页才算可发布页**。
- **审核要点**：一键生成进度反馈是否清晰；成图质量与色彩模式正确性（partial 背景灰调人物彩色）。

### T6.2 页画廊 + 页详情 + 对比视图
- **产出**：PageGallery（按话分组缩略图、状态角标、懒加载）、PageDetail（布局图 vs 成品图对比 CompareViewer、脚本编辑、重生成布局/成图、单页下载）。
- **验收**：画廊 100+ 页滚动流畅；页详情对比视图可拖动分界；单页重生成后画廊与详情同步更新。

### T6.3 页级后处理：上色 / 清晰化 / 局部重绘
- **产出**：COLORIZE/CLEAN/REPAINT 任务；MaskPainter 组件（笔刷/矩形/橡皮/撤销，导出 mask→OSS）；生成记录保留（page.generate_records JSON，可回看历史版本）。
- **验收**：黑白页一键上色（色彩正确）；清晰化提升细节；框选区域重绘仅改动选区；历史版本可切换查看。

## Phase 7 管理后台收尾 + 导出 + 收尾打磨

### T7.1 系统配置 / 提示词 / 风格预设管理页
- **产出**：/admin/configs（分组表单 + verify 按钮 + 并发参数）、提示词 Tab（各环节模板编辑 + 占位符说明 + 恢复默认）、/admin/presets（预设 CRUD + 参考图上传）；创建作品弹窗支持选风格预设。
- **验收**：修改生图模型后无需重启即生效；提示词修改后下一次脚本生成即使用新模板；新建作品选择预设后 stylePrompt 进入生成链路。

### T7.2 全局任务监控 + 导出
- **产出**：/admin/tasks（全用户任务 + 按用户筛选 + 停止/重试）、/admin/overview 概览卡（运行中/排队/通道占用）；`GET /api/projects/{id}/export` 导出包：按话图片目录 **+ 根目录 manifest.json（遵循 comic-content-1.0，chapters/pages 升序，仅含 generate_status=2 且有 generated_image_url 的正式页；存在缺图页默认拒绝生成正式发布包，allowPartial=true 管理员参数可调试导出并标记 complete=false；不导出 user_id/task/提示词/失败日志/style_preset_id）**；前端导出入口。
- **验收**：导出包解压目录结构与命名正确；**manifest.json 符合 comic-content-1.0 且可在空数据库中重建"漫画→话→页"阅读结构**；概览数字与实际任务一致。

### T7.3 端到端验收 + 体验打磨
- **产出**：全流程回归（批量上传 3 部 → 第一步并行 → 编辑资产 → 3 部同时一键出图 → 后处理 → 导出）；空态/错误态/加载态统一检查；部署文档 `v2/docs/04-部署手册.md`（含 Nginx 配置样例）。
- **验收**（对应 01 文档 §6 非功能需求）：3 部剧并行 BATCH 成功；服务重启后任务自动恢复；进度推送 ≤2s；USER 全程接触不到任何系统配置。

## 附：执行约定

1. 每任务完成 = 代码可运行 + 验收标准自测通过 + 简要说明（改动点/自测结果/截图或关键输出），提交用户审核。
2. 审核发现问题 → 修复后重新提交同一任务；通过 → 下一任务。
3. 实现与文档冲突时：先改文档（本目录），再改代码。
4. 提交粒度：每任务一个 git commit（message：`v2(Tx.y): 摘要`）。
