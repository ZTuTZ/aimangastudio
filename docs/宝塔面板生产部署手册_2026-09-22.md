# AIMangaStudio v2 宝塔面板生产部署手册

本文用于将当前 V2 项目部署到一台已安装宝塔 Linux 面板的服务器。当前上线形态限定为**单个后端实例**：Nginx 提供前端静态文件和 HTTPS，并把 `/api` 转发到本机 `127.0.0.1:8090`；Spring Boot 使用 MySQL 8、Redis 和阿里云 OSS。

宝塔官方也建议 Spring Boot 项目直接以可执行 JAR 运行，并由“网站 → Java 项目”配置 JDK、启动命令和环境变量。面板字段随版本可能略有变化，可对照[宝塔 Linux 面板 Java 项目部署教程](https://docs.bt.cn/practical-tutorials/Java-Project-Deployment-Tutorial)。

## 1. 上线拓扑与最低配置

```text
浏览器
  │ HTTPS 443
  ▼
宝塔 Nginx
  ├─ /              → frontend/dist 静态文件
  └─ /api           → 127.0.0.1:8090 Spring Boot
                           ├─ 127.0.0.1:3306 MySQL 8
                           ├─ 127.0.0.1:6379 Redis
                           └─ HTTPS → AI 网关 / 阿里云 OSS
```

测试期建议配置：

- Linux x86_64/arm64，4 核 CPU、8 GiB 内存、80 GiB 可用磁盘。
- JDK 17。不要使用低于 17 的 JDK。
- Node.js 20 只用于构建前端；如果在本地或 CI 构建，服务器不用安装 Node.js。
- MySQL 8.0，字符集 `utf8mb4`。
- Redis 6 或更高版本，只监听本机并设置密码。
- Nginx，由宝塔管理证书和站点。
- 阿里云 OSS。当前程序返回对象的直接 HTTPS 地址，因此 Bucket 或绑定的 CDN 域名必须允许用户读取这些对象。

生产机只开放 `22`、`80`、`443`。不要向公网开放 `8090`、`3306`、`6379` 或宝塔面板默认端口；宝塔面板应改端口、启用 HTTPS，并限制允许访问的 IP。

## 2. 发布包构建

在干净的 V2 源码目录构建。先完成测试，再生成发布包：

```bash
cd server
JAVA_HOME=/path/to/jdk-17 mvn -B clean verify
JAVA_HOME=/path/to/jdk-17 mvn -B -DskipTests package

cd ../frontend
npm ci
npm run lint
npm test -- --run
npm run build
```

需要上传到服务器的内容：

```text
server/target/aimanga-v2-server.jar
frontend/dist/ 目录中的全部文件
```

不要上传源码中的 `application-local.yml`、`.env`、数据库密码、JWT 密钥、AI 密钥或 OSS 密钥。

推荐在服务器创建以下目录：

```text
/www/server/aimanga/
  aimanga-v2-server.jar
  app.env
  logs/
  releases/

/www/wwwroot/aimanga/
  index.html
  assets/
```

文件权限建议：JAR 和前端文件为 `644`，目录为 `755`，`app.env` 为 `600`。运行 Java 的系统用户只需要读取 JAR、读取环境文件和写日志的权限。

## 3. 在宝塔安装运行环境

在“软件商店”安装：

1. Nginx。
2. MySQL 8.0。
3. Redis。
4. Java 项目管理器和 JDK 17。若面板版本没有 Java 项目管理器，可安装 Supervisor 管理器，按第 7 节备用方式运行。

安装完成后，在宝塔终端确认：

```bash
java -version
mysql --version
redis-cli --version
nginx -v
```

`java -version` 必须显示 17。

## 4. 创建 MySQL 数据库

在宝塔“数据库”中创建：

| 项目 | 建议值 |
|---|---|
| 数据库名 | `aimanga_v2` |
| 用户名 | `aimanga` |
| 密码 | 使用宝塔生成的高强度随机密码 |
| 访问权限 | 本地服务器 |
| 字符集 | `utf8mb4` |

不要导入 `server/sql/schema.sql` 或重复执行历史 SQL。应用第一次启动时由 Flyway 自动创建和升级数据库。

发布前在宝塔“数据库 → 备份”创建一次完整备份。后续建议每天自动备份，至少保留 7 天，并定期把备份复制到服务器之外。

## 5. 配置 Redis

在宝塔 Redis 设置中：

1. 绑定 `127.0.0.1`。
2. 设置强密码。
3. 禁止安全组和系统防火墙开放 6379。
4. 保持持久化功能开启；任务事实状态在 MySQL，Redis 仍承担队列和并发许可。

验证：

```bash
redis-cli -h 127.0.0.1 -a '实际Redis密码' PING
```

应返回 `PONG`。不要把真实密码写入命令历史；正式操作可先设置临时 `REDISCLI_AUTH` 环境变量。

## 6. 创建生产环境变量

在宝塔 Java 项目的“环境变量”中逐行填写下面的键值。宝塔官方 Java 项目页面支持 `KEY=VALUE` 多行格式。也可以把相同内容保存为 `/www/server/aimanga/app.env`，供第 7 节备用启动脚本使用。

```dotenv
SPRING_PROFILES_ACTIVE=prod
SERVER_PORT=8090
SERVER_ADDRESS=127.0.0.1

DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=aimanga_v2
DB_USER=aimanga
DB_PASSWORD=替换为数据库强密码

REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_DATABASE=0
SPRING_DATA_REDIS_PASSWORD=替换为Redis强密码

JWT_SECRET=替换为至少32字节的随机密钥

AIMANGA_BOOTSTRAP_ADMIN_USERNAME=替换为初始管理员账号
AIMANGA_BOOTSTRAP_ADMIN_PASSWORD=替换为初始管理员强密码
```

生成 JWT 密钥可使用：

```bash
openssl rand -base64 48
```

注意：

- `JWT_SECRET` 改变后，所有已登录会话都会失效。
- 初始管理员只在数据库中不存在 ADMIN 时创建。首次登录成功后可以从环境变量中删除两个 `AIMANGA_BOOTSTRAP_*` 项并重启；已有管理员不会被删除。
- AI 和 OSS 密钥推荐在首次登录后的“系统配置”页面填写。它们保存在数据库中，数据库备份必须按敏感数据保护。
- 密码包含空格、`#`、引号或 shell 特殊字符时，优先使用宝塔 Java 项目的环境变量输入框。若使用 `app.env`，必须按 shell 语法正确加单引号。

## 7. 启动 Spring Boot 后端

### 7.1 推荐：宝塔 Java 项目

进入“网站 → Java 项目 → 添加 Java 项目”：

| 字段 | 值 |
|---|---|
| 项目类型 | Spring Boot |
| 项目名称 | `aimanga-v2-server` |
| JAR 路径 | `/www/server/aimanga/aimanga-v2-server.jar` |
| JDK | 17 |
| 项目端口 | 8090 |
| 开机启动 | 开启 |
| 外网映射 | 不直接暴露；由前端站点 Nginx 反代 |

启动命令使用面板选择的 JDK 17 路径：

```bash
java -Xms512m -Xmx2048m -XX:+ExitOnOutOfMemoryError -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai -jar /www/server/aimanga/aimanga-v2-server.jar
```

把第 6 节的环境变量填入项目环境变量。启动后先查看 Java 项目日志，不要立即开放域名。

### 7.2 备用：宝塔 Supervisor

如果面板没有 Java 项目功能，创建 `/www/server/aimanga/start.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail
set -a
. /www/server/aimanga/app.env
set +a
exec /usr/bin/java \
  -Xms512m -Xmx2048m \
  -XX:+ExitOnOutOfMemoryError \
  -Dfile.encoding=UTF-8 \
  -Duser.timezone=Asia/Shanghai \
  -jar /www/server/aimanga/aimanga-v2-server.jar
```

```bash
chmod 700 /www/server/aimanga/start.sh
chmod 600 /www/server/aimanga/app.env
```

在 Supervisor 管理器中添加：

| 字段 | 值 |
|---|---|
| 名称 | `aimanga-v2-server` |
| 启动用户 | 受限普通用户，例如 `www` |
| 运行目录 | `/www/server/aimanga` |
| 启动命令 | `/www/server/aimanga/start.sh` |
| 自动启动 | 开启 |
| 异常自动重启 | 开启 |
| 日志 | `/www/server/aimanga/logs/server.log` |

不要同时启用 Java 项目和 Supervisor，否则会启动两个 Worker 实例。

## 8. 首次启动和数据库迁移

启动后查看日志，必须满足：

1. Flyway 没有 checksum、validation 或 migration failed 错误。
2. MySQL 与 Redis 连接成功。
3. 端口 8090 只监听本机或被防火墙阻断公网访问。
4. 初始管理员创建成功，或日志明确表示数据库中已有管理员。
5. `ss -lntp | grep 8090` 显示后端监听 `127.0.0.1:8090`，而不是 `0.0.0.0:8090`。

服务器本机检查：

```bash
curl -fsS http://127.0.0.1:8090/api/health
```

响应中的 `db`、`redis`、`status` 都应为 `UP`。

在 MySQL 中检查迁移：

```sql
SELECT installed_rank, version, description, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

当前版本应至少包含 `8.1.4` 且全部 `success=1`。不要手工修改 `flyway_schema_history`，也不要编辑已经发布的迁移文件。

## 9. 部署前端静态站点

在宝塔“网站 → 添加站点”创建域名，例如 `manga.example.com`：

- 网站根目录：`/www/wwwroot/aimanga`
- PHP：纯静态
- 默认文档：`index.html`

把 `frontend/dist/` 内的全部文件上传到网站根目录。不要多套一层 `dist` 目录。

在站点 Nginx 配置中保留宝塔生成的 SSL/日志段，并加入下面的站点主体配置：

```nginx
client_max_body_size 200m;

root /www/wwwroot/aimanga;
index index.html;

location = /api/tasks/events {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 3600s;
    access_log off;
    add_header X-Accel-Buffering no;
}

location /api/admin/export/artifacts/ {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}

location /api/ {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
}

location /assets/ {
    try_files $uri =404;
    expires 30d;
    add_header Cache-Control "public, immutable";
}

location / {
    try_files $uri $uri/ /index.html;
}
```

保存前使用宝塔的配置检测，或执行：

```bash
nginx -t
```

检测成功后重载 Nginx。

## 10. HTTPS、域名和 OSS

1. 在宝塔站点“SSL”中申请 Let's Encrypt 证书。
2. 开启强制 HTTPS。
3. 确认域名 DNS 已指向服务器。
4. OSS Bucket 为图片和导出对象配置 HTTPS 访问。若浏览器需要直接读取对象，设置来源域名允许 `GET`、`HEAD`，并只开放业务需要的跨域头。
5. OSS AccessKey 使用最小权限，只允许目标 Bucket 中本系统使用的前缀。系统需要读、写、删除导出对象。

从公网验证：

```bash
curl -fsS https://manga.example.com/api/health
```

不要以 `http://服务器IP:8090` 作为正式访问入口。

## 11. 首次业务配置

使用初始管理员登录后，进入“系统配置”依次填写并验证：

1. 文本 AI：地址、API Key、模型、协议、超时、并发。
2. 生图 AI：地址、API Key、模型、协议、超时、并发。
3. 编辑 AI：如需上色、清晰化或局部重绘再配置。
4. OSS：AccessKey、Secret、Bucket、Region、Endpoint。
5. 任务并发：测试期从较小值开始，例如全局 2、单用户 1。
6. 批量导出：最大作品数、最大包字节数、临时磁盘总预算、检查点与最终产物保留时间、上传和下载超时。`export_max_bytes` 与 `export_temp_max_bytes` 支持 64 位正整数，例如 8 GiB 为 `8589934592`。临时磁盘预算应小于服务器 `/tmp` 可用空间，并为系统和其他服务保留余量。

先使用“验证”按钮测试文本和生图 AI。OSS 通过上传一张参考图并完成一次小型导出验证读、写、删除权限，再开放普通用户。

## 12. 上线验收清单

按顺序执行，任一步失败都先停止开放测试：

- [ ] `https://域名/api/health` 返回 MySQL、Redis、总状态均为 `UP`。
- [ ] 管理员可以登录，刷新页面后仍保持登录。
- [ ] 系统配置保存后重启后端，配置仍存在；密钥在页面显示为掩码。
- [ ] 上传一个小型 TXT，完成拆话、资产、脚本流程。
- [ ] 创建一个小范围生图任务，任务进度实时更新；浏览器 SSE 连接不频繁断开。
- [ ] 暂停并继续任务，确认继续的是同一个任务。
- [ ] 导出两部小作品，下载 ZIP 并执行 `unzip -t 文件.zip`，全部 entry 校验通过。
- [ ] 制造一个部分成功导出后点击重试，新下载包的字节数和 SHA256 已变化，并包含重试成功的作品。
- [ ] 删除或等待最终导出包过期后，同一任务按允许的操作仍能基于保留的检查点重新生成最终包。
- [ ] 观察 30 分钟日志，无持续 heartbeat、ownership、Redis permit 或导出清理错误。

## 13. 日常升级步骤

本版本新增 `V8_1_5__export_lifecycle.sql`，会建立导出对象与下载读租约表，并扩展最终产物的发布代次。升级必须整体切换，不能让旧版本清理器与新版本同时运行：

1. 在页面通知维护时间，暂停创建新任务。
2. 在管理端任务监控确认 RUNNING、STOPPING 数量为 0；仍运行的任务先等待、暂停或停止。
3. 宝塔备份 MySQL，并记录当前 JAR 和前端发布目录。
4. 上传新文件为 `aimanga-v2-server.jar.new`，前端上传到新的临时目录。
5. 停止 Java 项目，确认旧进程完全退出，避免旧清理器继续删除对象。
6. 把旧 JAR 改名为带时间戳的备份，再将 `.new` 原子改名为正式 JAR。
7. 替换前端静态目录；先保留上一版目录，不立即删除。
8. 启动 Java 项目，观察 Flyway 完成 `8.1.5`，确认 `export_stored_object` 与 `export_object_read_lease` 已建立；不要手工改 Flyway 历史。
9. 等待历史导出对象回填任务运行，检查日志中是否有“历史产物待人工处理”。这类记录通常表示旧 URL 不属于当前 OSS 配置，系统不会自动删除。
10. 检查 `/api/health`，重载 Nginx，执行第 12 节的小范围验收，再恢复用户访问。

不要在正在运行任务时直接杀掉旧后端并同时启动新后端。当前测试部署只允许一个后端实例。

## 14. 回滚

如果新版本无法启动或核心流程失败：

1. 立即在宝塔停止 Java 项目，并把站点切到维护页。
2. 保存新版本日志和当前数据库备份，不要清空 Redis 或删除 OSS 文件。
3. 数据库采用向前修复，不删除 `V8_1_5` 新增的列、表或对象清理记录，也不要手工改 Flyway 历史。
4. 若必须恢复旧 JAR，先保持导出入口关闭，并确保新旧版本不会同时运行清理任务；旧版本不了解新的对象状态，不应继续处理导出。
5. 优先发布修正版新 JAR 恢复服务，检查 `/api/health` 和任务监控后再开放导出。

恢复后检查 PENDING/PAUSED 任务是否正常补偿。不要直接把数据库中的 RUNNING 状态手工改为成功。

## 15. 备份、日志与告警

- MySQL：每天自动备份，至少保留 7 天；每月做一次恢复演练。
- OSS：建议开启版本控制或生命周期规则。生命周期规则不能早于应用的导出保留时间，也不能误删生成图片前缀。
- Java 日志：在宝塔设置按天切割和保留期限，至少保留 14 天；限制单文件大小。
- Nginx：保留访问日志和错误日志，关注 499、502、504。
- 监控：关注任务长期 PENDING、Worker 数量不足、heartbeat 失败、ownership lost、permit renew failure、导出失败和磁盘使用率。
- 磁盘：`/tmp/aimanga-export` 会承载下载中的图片、单本 ZIP、检查点和最终 ZIP。建议在 70% 告警、85% 停止新增大导出。

## 16. 当前生产边界

本版本已统一任务数据库准入事务，并加入导出发布代次 fencing、持久下载读租约、独立对象清理队列、检查点重建和单进程临时磁盘总预算。代码和容器集成测试通过后可以继续单实例运行。

若服务器是在 2026-09-25 的 eb682b7 提交之前部署的，须按第 13 节的停领任务、备份、排空和整体切换步骤更新后端 JAR，并核对 Flyway 已到 V8_1_5。329fcfd 把下载中的图片纳入 export_temp_max_bytes；eb682b7 修复多本检查点合计超额后仍发布部分成功包的问题。更新后检查导出任务与 /tmp/aimanga-export 的实际用量，再决定额度。

本地开发机已用 20×300,000,000 字节不可高度压缩流通过外层生产组包路径验收：最终 ZIP 6,001,833,141 字节，临时文件采样峰值 6,259,720,233 字节，详见《导出6GB压力验收记录》。这不能代替预发布机器的真实 OSS、磁盘满和并行任务演练；预发布机仍须核对 /tmp 实际可用空间并显式提高 export_max_bytes 与 export_temp_max_bytes。当前临时目录按进程隔离，多个 JVM 各自执行预算；在完成多实例共享磁盘配额与真实 OSS 压测前，宝塔仍只运行一个后端实例。GitHub main 分支保护也需要在仓库设置中把 backend-verify 与 frontend-checks 设为必需检查。

## 17. 常见故障

| 现象 | 检查项 |
|---|---|
| 502 Bad Gateway | Java 项目是否运行；8090 是否监听；Nginx `proxy_pass` 是否为 `127.0.0.1:8090` |
| 健康检查 DB DOWN | 数据库名、用户、密码；MySQL 是否只允许错误的来源；Flyway 日志 |
| 健康检查 Redis DOWN | `SPRING_DATA_REDIS_PASSWORD`、Redis bind、端口和服务状态 |
| 登录后重启即失效 | `JWT_SECRET` 未固定或长度不足 32 字节 |
| 页面刷新 404 | Nginx 缺少 `try_files $uri $uri/ /index.html` |
| 任务进度不实时 | SSE location 被缓存；确认 `proxy_buffering off` 和 3600 秒读取超时 |
| 上传返回 413 | Nginx `client_max_body_size` 小于应用 200 MB 限制 |
| 导出失败或磁盘满 | `/tmp` 空间、`export_max_bytes`、`export_temp_max_bytes`、OSS 读写权限和网络；清理失败会保留记录并退避重试 |
| 导出下载 409/410 | 任务未到 SUCCESS/PARTIAL，或产物已经过期 |
| OSS 图片打不开 | Bucket/CDN 读取权限、Region、Endpoint、HTTPS 和 CORS |
