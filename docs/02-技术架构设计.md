# v2 技术架构设计

> 后端：Java 17 + Spring Boot 3.3 + Apache Shiro（认证/授权）+ MyBatis-Plus + MySQL 8 + Redis（Redisson）+ 阿里云 OSS。
> 前端：React 18 + Vite 5 + TypeScript + Ant Design 5 + Tailwind CSS + React Router 6 + TanStack Query 5。
> 部署：手动（jar + Nginx 静态托管 + 反代 /api 与 /sse）。

## 1. 总体架构

```
浏览器 (React SPA, AntD)
   │  HTTPS
   ▼
Nginx
   ├── /            → frontend/dist 静态资源
   ├── /api/*       → http://127.0.0.1:8090  (Spring Boot)
   └── /sse/*       → 同上（SSE 长连接，需关闭缓冲 proxy_buffering off）
   ▼
aimanga-v2 (Spring Boot, :8090)
   ├── controller    REST API + SSE 端点
   ├── service       业务服务（project/chapter/page/asset/task/config/prompt）
   ├── ai            AiService（多供应商兼容）+ PromptService + AiClient 限流
   ├── pipeline      生成流水线（SPLIT 滚动分包拆话 → ASSET 分包提取+全局合并 → SCRIPT×N 全局资产+页级覆盖 → SHEET → LAYOUT/PAGE/COLORIZE/CLEAN/REPAINT/BATCH；text/SourceTextIndexer 原文索引层）
   ├── task          任务系统：TaskQueue(Redisson) + TaskWorker 池 + TaskRunner + 状态机 + 恢复器
   ├── security      Apache Shiro（无状态 JWT）+ 角色
   ├── storage       OssStorageService
   └── repository    MyBatis-Plus Mappers
        │                    │
      MySQL 8             Redis 6+ (Redisson)
   (业务数据+任务事实)    (队列/信号量/进度缓存/Pub-Sub)
        │
      阿里云 OSS ← 所有图片统一转存，仅存 URL
        │
      AI 网关（GeekAI 兼容：Gemini generateContent / OpenAI images 双协议）
```

**职责划分原则**：
- MySQL = 业务数据 + 任务**事实**（状态、计数、结果）。Redis 数据全部可丢可重建。
- Redis = 队列、并发许可、进度缓存、事件广播。
- 前端永远不接触 AI Key / OSS 密钥；一切 AI 与存储调用由后端代持。

## 3. 认证与权限

- **Apache Shiro + 无状态 JWT**（不引入 Spring Security）：Shiro 仅承担认证/授权骨架——自定义 `Realm`（查 user 表做凭证校验与角色装载）+ 自定义 JWT Filter；禁用 Shiro 默认 Session/Cookie，Subject 生命周期绑定单次请求。
- Token 方案：`POST /api/auth/login` 签发 access(2h) + refresh(7d，存 Redis 可吊销)；`POST /api/auth/refresh` 轮换。不做登录失败锁定。
- 密码 BCrypt 哈希存储。
- 两个角色：`ADMIN`、`USER`。`/api/admin/**` 仅 ADMIN（Shiro 注解/过滤链配置）。
- 数据隔离：Service 层强制 `project.user_id == 当前用户 || 当前用户是 ADMIN`，任务/资产/页均经 project 归属校验。
- 前端：路由守卫 + axios 拦截器（401 → 刷新 → 重放；失败 → /login）。

## 4. 任务系统设计（核心）

### 4.1 原则

- **MySQL 为事实**：任务行（状态/进度/计数）持久化；Redis 只做调度与加速，任意时刻 Redis 数据丢失可重建（从 MySQL 扫描恢复）。
- **推拉结合**：Redisson 队列拉取 + Redis Pub/Sub 推送进度到 SSE。

### 4.2 任务生命周期

```
API 创建任务 → MySQL 插入 status=PENDING(0) → RPUSH aimanga:v2:task:queue {taskId}
TaskWorker(N 个常驻线程，N=全局最大并行任务数) BLPOP 领取
  → 每用户并发许可（Redisson Semaphore aimanga:v2:sem:user:{uid}，tryAcquire 失败→重新入队并延迟 2s）
  → MySQL status=RUNNING(1), start_time → 执行 pipeline
  → 每页/每步完成：更新 MySQL 计数 + Redis 进度缓存 + PUBLISH aimanga:v2:events {taskId,progress,...}
  → 终态写 MySQL(SUCCESS/FAILED/PARTIAL/STOPPED, end_time)
```

- **停止**：`POST /tasks/{id}/stop` → status=STOPPING(6)；执行器在**每个原子步骤前**检查 DB 状态，感知后写 STOPPED(5)；仍在队列中的任务直接置 STOPPED 不再执行。
- **重试**：`POST /tasks/{id}/retry` → 校验非进行中 → status=PENDING，保留 `current_no`（BATCH 从失败页续跑；payload.force 可全量重跑）→ 重新入队。
- **重启恢复**：`ApplicationReadyEvent` → 扫描 `status IN (PENDING, RUNNING, STOPPING)` → 全部重置为 PENDING → 重新入队。页级幂等保证不重复生成。

### 4.3 并发控制（四层，全部可配置）

| 层 | 机制 | 配置项（system_config） | 默认 |
|---|---|---|---|
| ① 全局并行任务数 | TaskWorker 线程数 | `task_max_concurrency` | 5 |
| ② 每用户并行任务数 | Redisson Semaphore per uid | `task_user_concurrency` | 2 |
| ③ 单任务内页级并发 | TaskRunner 内部固定线程池（CompletableFuture 分批） | `task_page_concurrency` | 5 |
| ④ AI 通道并发 | Redisson Semaphore per channel(text/image/merge) | `ai_{channel}_concurrency` | text 15 / image 10 / merge 10 |

- ①③ 用 JVM 线程池即可（单实例部署）；②④ 用 Redis 信号量（为将来多实例预留，单实例也无损）。
- 配置热更新：保存配置后刷新 Redisson 信号量容量（`trySetPermits`）与 worker 池（重建线程池，旧池优雅关闭）。

### 4.4 任务类型与流水线

| task_type | 输入(payload) | 执行 |
|---|---|---|
| `SPLIT` | projectId | 拆话（有已生成页则拒绝），完成后自动为每话入队 SCRIPT |
| `SCRIPT` | projectId, chapterId | 六段式脚本 → 写 chapter/page + 建资产 → （开关）自动入队 ASSET |
| `ASSET` | projectId | 从脚本提取四类资产并结构化（同人合并 aliases） |
| `SHEET` | projectId, assetId? | 生成资产设定表（角色=六姿势） |
| `BATCH` | projectId, chapterId?, colorMode, skipGenerated | 逐页 LAYOUT→PAGE（页级并发），支持断点续跑 |
| `PAGE` | pageId, colorMode | 单页重生成（含布局图） |
| `LAYOUT` | pageId | 单页布局图 |
| `COLORIZE` / `CLEAN` | pageId | 整页后处理 |
| `REPAINT` | pageId, mask(dataURL→OSS), prompt | 局部重绘 |

- 第一步流水线编排（SPLIT→SCRIPT×N→ASSET→SHEET）通过**任务链**实现：父任务结束时按条件子任务入队（子任务独立可见、可单独停止/重试），避免单个巨型任务不可控。
- BATCH 内部：先确保该范围脚本就绪（缺则报错提示先完成第一步）→ 收集页 → 过滤空脚本页/已生成页（skipGenerated）→ 页级并发执行 → 失败页写 fail_reason，任务终态 PARTIAL + `result.failedPages`。

### 4.5 进度推送（SSE）

- 端点：`GET /api/tasks/events`（EventSource，带 token query 参数或 cookie）。
- 后端：`SseEmitter` 注册表 + Redis 订阅 `aimanga:v2:events`（channel 内含 userId，服务端按归属过滤推送；ADMIN 可订阅全局频道）。
- 事件：`task.created / task.progress / task.status / page.generated(projectId,pageId,url)`。
- 前端：TanStack Query 缓存 + SSE 事件触发 `invalidateQueries`；SSE 断线自动重连，期间任务列表降级 5s 轮询。

### 4.6 幂等与一致性

- PAGE 执行前检查：`generate_status==2 且有 URL 且 !force` → 跳过并计入成功（BATCH 续跑基础）。
- 空脚本页不生成（沿用旧版经验教训）。
- 任务对 project/chapter 的写操作与状态更新在同一事务；图片 OSS 上传成功后才写 DB URL。

## 5. AI 服务层（`ai` 包）

沿用旧版成熟思路重写：
- `AiClient`：HTTP 客户端（超时/重试/日志）；双协议——Gemini 兼容 `POST {url}/v1beta/models/{model}:generateContent`（支持 imageConfig.aspectRatio 与参考图 inlineData/fileData），OpenAI 兼容 `POST {url}/v1/images/generations`（size 映射 + 参考图）。
- `AiService`：`chat(channel,prompt,images)` / `chatJson(channel,prompt,clazz)`（失败重试 1 次）/ `generateImage(channel,prompt,images,aspectRatio)`；响应解析兼容 OpenAI choices / Gemini candidates / 直返 URL / base64；所有产出图经 `OssStorageService` 转存。
- `PromptService`：模板存 system_config（`prompt_*`），占位符 `{text}/{aspect}/{characters}/{page_count}/{style}/{color_mode}/{prev_page}`；代码内置默认模板兜底。
- **契约校验**（SCRIPT 产物）：pages 非空、无空页、dialogue.speaker 必须存在于资产/角色集、旁白与对白无标点（校验失败自动重试 1 次，再失败则任务失败并带原因）。

## 9. 部署（手动）

### 9.1 本机开发环境（已确认）

| 组件 | 说明 |
|---|---|
| Maven | `/Users/aadmin/tool/apache-maven-3.9.16`（构建用 `mvn`，必要时显式指定该路径） |
| MySQL 8 | 本机实例，账号 `root` / 密码 `202151259`（开发库连接串按此配置；生产部署时改用环境变量注入） |
| Redis | Homebrew 安装的本机 Redis（默认 `localhost:6379`） |
| Node.js | 前端构建需要 Node 18+ |

### 9.2 部署步骤

1. MySQL：建库 `aimanga_v2`（utf8mb4），执行 `v2/server/sql/schema.sql` + `seed.sql`（开发环境直接用上述 root 账号）。
2. Redis：`brew services start redis`（或已随 brew 常驻）。
3. 后端：`mvn package`（v2/server）→ `java -jar v2-server.jar`，环境变量 `DB_*` / `REDIS_*` / `JWT_SECRET`（生产必填，无默认值；开发环境可在 `application-local.yml` 提供本地默认）。
4. 前端：`npm run build` → `frontend/dist` 交 Nginx；Nginx 反代 `/api`（含 SSE：`proxy_buffering off; proxy_read_timeout 1h`）。
5. 端口约定：后端 8090（避开旧版 8080，两版可并存）。
