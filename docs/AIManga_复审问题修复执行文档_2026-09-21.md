- [ ] checkpoint 有独立保留期，例如 `export_checkpoint_ttl_hours=168`；超期清理后的 retry 允许重建，对应 Unit 的 SUCCESS 必须原子改为 PENDING，并清除旧 resultRef、attempt/finish/error。仅操作该 Task/planVersion/Unit，不能重置其他任务的 Stage Item。
- [ ] 旧 SUCCESS 但文件已不存在、长度或 SHA256 不符，不能视为成功：在下载时流式核验，用 owner CAS 标记需重建并进入有限次重建流程。外部 HEAD/下载在事务外，判定写入时重新校验 owner。
- [ ] 每本 checkpoint 最多在同次执行中额外重建一次；仍失败时记录该本失败并继续其他本。下载、校验和重建必须在向外层 ZIP 写入该本 entry 之前完成；一旦外层 ZIP 写入本身失败则整个最终发布失败，不能继续宣称 ZIP 完整。最终 Task 统计从本次实际包内容重算，不能保留重建前的成功计数。
- [ ] planningError 类型的失败在固定快照下仍失败时，明确提示创建新导出任务；不要在 retry 中偷偷用最新内容替换原快照。
- [ ] 已 EXPIRED 的 artifact 行可以领取新 generation 并重新发布，不能被原来的 status=0 条件永久卡住。

### T5.2 可重试清理

- [ ] 禁用原 selectCleanupCandidates“FAILED/STOPPED 立即删所有文件”的路径，改为以独立对象记录和保留期限选候选。
- [ ] 清理事务按约定锁序复查 Task 状态、产物当前引用和下载读租约；无可用 Task 时依然允许清理。确认无使用者后 CAS 为 DELETING，写唯一 cleanup_token/lease，再提交。
- [ ] 事务外执行存储删除；成功后按 token CAS 为 DELETED；失败保留 key/错误/重试次数，按退避时间重试。对象已不存在视为删除成功。
- [ ] DELETING 租约到期后另一清理实例可接管；正在删除的对象不能被 retry 重新引用。
- [ ] 补竞争测试：清理扫描后 retry、两个清理实例同时处理、删除失败、进程在远程删除后崩溃、下载与到期清理竞争。

### T5.3 用户删除任务

- [ ] delete 改为事务内锁 Task、重新核对终态，然后把该任务所有对象加入持久清理队列，再按合法源状态删除 Task。与 retry 的锁/CAS 配合，不能读到终态后无条件删除刚恢复的任务。
- [ ] 新对象记录无级联外键，Task/artifact/plan 删除后仍保留存储 key；历史未登记对象必须先登记，失败则本次删除回滚。
- [ ] 用户删除时不在数据库事务内执行 OSS 操作；后续清理失败也不丢失记录。
- [ ] 测试成功/部分成功/失败/停止任务删除，以及 delete 与 retry 竞争；必须至多一方成功，不能删除运行中的任务。

**测试命令：** `mvn -B -Dit.test=ExportLifecycleIT verify`。

**完成标准：** 同任务可按规则恢复；文件被清理后可从快照重建；任务删除不会泄漏清理索引；清理不破坏运行或下载中的文件。

## T6. long 额度与流式临时磁盘预算

**文件：** 修改 `service/ConfigService.java`、配置保存校验入口、`pipeline/ExportTaskHandler.java`、`pipeline/PublicationService.java`、`storage/StorageService.java`、`storage/OssStorageService.java`；新增 `pipeline/ExportIoBudget.java`、`pipeline/ExportTempFiles.java`；新增 `db/migration/V8_1_6__export_budget_defaults.sql`、`pipeline/ExportIoBudgetTest.java`、`integration/ExportResourceIT.java`；必要时同步前端配置表单的范围限制。

- [ ] 添加测试：字符串 `8589934592` 可作为 8GiB long 读取；负数、非数字、long 溢出在保存配置时返回明确错误，不能悄悄退回 1GiB。
- [ ] ConfigService 增加 `long getLong(String key, long defaultValue)`；空配置用默认值，已配置却无效的导出额度抛明确配置错误。保留其他 getInt 行为以控制范围。
- [ ] 新配置均使用 long：`export_max_bytes` 默认仍为 1GiB；`export_checkpoint_ttl_hours` 使用已有 T5 约定；临时预算 `export_temp_max_bytes` 默认 2GiB。迁移只填缺失键，不覆盖已有值。部署文档写明 6GB 压测须显式提升额度与磁盘预算。
- [ ] 增加写入前检查的计数 OutputStream，下面是边界算法；used/limit 均为 long，避免加法溢出：

```java
if (length < 0 || used > limit || (long) length > limit - used) {
    throw new IOException("导出大小超过配置限制");
}
out.write(bytes, offset, length);
used += length;
```

- [ ] 同时覆盖 write(int)、write(byte[],off,len)，避免 FilterOutputStream 的默认委派造成重复计数。限制要包括 ZIP header/manifest/summary，不只是图片大小之和。
- [ ] PublicationService 图片临时下载、单本 ZIP、checkpoint 下载、外层 ZIP 全部进入同一临时文件登记/预算机制；不能只包住外层 ZIP 而遗漏先下载全部图片的路径。
- [ ] StorageService 使用受预算控制的 OutputStream 复制 checkpoint，并边复制边算 SHA256。停止/暂停及额度检查按固定块执行，避免一次完整 copy 后才检查。
- [ ] ExportTempFiles 按节点共享临时目录原子预留磁盘额度，所有并行任务共用计数；实际删除文件成功后才释放预算。多 JVM 若共用同一目录，要以文件锁保护同一账本；部署到不同目录则各自预算，并明确磁盘配额。
- [ ] 预算未满足时任务给出可重试的资源不足原因，不能破坏成功 checkpoint；系统磁盘满也必须关闭流、登记残留、阻止 publish。
- [ ] 节点启动扫描遗留临时文件，依据工作租约/锁回收孤儿，不盲删其他运行实例的目录。
- [ ] 快速自动化覆盖：正好额度、超 1 字节、超长配置、并发预留、写中磁盘错误、取消、清理删除失败；大小测试以小额度跑同一算法，避免每次 CI 写 6GB。

**6GB 专项验收：** 20 本，每本 300,000,000 字节合成不可高度压缩流；不使用全量 byte[]，不调用 AI。设置最终产物额度 ≥8GiB，临时预算与可用磁盘根据实测下载/打包峰值配置；使用 `-Xmx512m`，记录每秒堆内存、临时磁盘峰值、耗时、实际 ZIP 字节数。用一个独立测试 JVM 实际调用导出生产路径，不能只测试裸 ZipOutputStream。

- [ ] 在 1/5/20 本阶梯下验证最大堆 ≤512MiB、无 OOM；最终包可逐项解压，校验各项摘要。
- [ ] 注入第 5 本读取失败，保留其他成功本及 summary；外层磁盘满则任务失败且没有可下载成功产物。
- [ ] 使用 Maven profile `export-stress` 仅启用独立 `ExportResourceStressIT`，命令 `mvn -B -Pexport-stress -Dit.test=ExportResourceStressIT verify`；在 profile 中配置测试 JVM `-Xmx512m`。普通 CI 不执行该大规模测试。

**完成标准：** 6GB 配置不溢出；超限即时终止；峰值堆不随产物大小线性增长；并行临时文件总量受限。压力环境不可用时，代码可标“已实现”，专项验收仍标“未执行”。
