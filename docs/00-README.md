# AIMangaStudio v2 — 规划总览与决策记录

> 本目录（`v2/`）是 AIMangaStudio 的全新重构版本。**不修改根目录下的旧版代码**，旧版保留作参考。
> 阅读顺序：`00-README`（本文）→ `01-需求与页面规格` → `02-技术架构设计` → `03-开发任务计划`。

## 1. 重构目标（一句话）

把"单用户漫画生成工具"重构成**多用户漫画生产平台**：用户可批量上传多个故事原文并**同时**进行准备流水线（拆话 → 分镜脚本 → 资产提取），再**一键生成成品页**（局部上色 / 黑白 / 全彩），底层是支持高并发、多任务并行、可限流、可恢复的 Redis 任务系统。

## 2. 产品形态：两步式生产流程

```
第一步【准备】（上传后自动流水线，多部剧并行）
  上传故事原文（TXT/DOCX/粘贴，支持一次多部）
    → SPLIT 拆话（长文按情节拆分为多话）
    → SCRIPT 六段式分镜脚本（逐话）
    → ASSET 资产提取（角色/场景/道具/服装，结构化设定）
    → SHEET 角色设定表（六姿势参考图，可配置自动）
  用户在此阶段可审核/编辑：话、脚本、资产

第二步【出图】（用户手动触发，一键）
  选择范围（整部剧 / 某一话）+ 色彩模式（局部上色 / 黑白 / 全彩）
    → 逐页 LAYOUT（AI 分镜布局图）→ PAGE（成品页）
  页级后处理：上色 COLORIZE / 清晰化 CLEAN / 局部重绘（遮罩+提示词）
  页级可单独重生成
```

| D11 | 生成粒度 | 整部剧一键 + 按话一键 + 页级重生成，三者都支持 |
| D12 | 后处理 | 全部保留：上色 / 清晰化 / 局部重绘（遮罩） |
| D13 | 多语言 | 保留 i18n 架构，**先只做中文**，en/ja 后续补 |

## 5. 核心设计摘要（详见 02 文档）

- **任务系统**：MySQL `task` 表是唯一事实来源（状态机），Redis 承担：任务队列（Redisson 延迟/普通队列）、全局与每用户并发信号量、AI 通道（text/image/merge）并发信号量、进度缓存、Pub/Sub 事件总线。前端通过 **SSE** 实时接收任务进度，任务列表另有轮询兜底。
- **并发分层**：全局最大并行任务数（worker 数）→ 每用户并行任务数 → 单任务内页级并发 → AI 通道全局信号量。四层均可由管理员在系统配置中调整。
- **可恢复**：服务重启时自动把 RUNNING/PENDING 任务重新入队；页级幂等（已成功页跳过），BATCH 支持从失败页续跑。
- **权限与数据隔离**：所有业务数据挂 `user_id`；USER 只能读写自己的剧/任务；ADMIN 可见全部。AI Key、OSS、提示词等系统配置仅 ADMIN 可读写，生成请求由后端代持密钥。
- **AI 契约**：提示词全部数据库配置（含六段式脚本契约），后端做契约校验（空页拒绝、对白 speaker 校验、逐字保留原文约束），失败自动重试。

## 6. 开发与交付方式

- 按 `03-开发任务计划` 的阶段（Phase 1~10）逐任务开发；**每个任务完成后提交给用户审核，审核通过才进入下一任务**。
- 每个任务定义了：目标、产出（文件/接口/页面）、验收标准（可操作的自测步骤）。
- 文档随实现进展更新（如 API 与实际实现出现偏差，先改文档再改码）。
